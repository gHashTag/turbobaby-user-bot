# TurboBaby — шаблон запуска новой копии бота

Пошаговый гайд, чтобы поднять новую копию этого бота-магазина (другой магазин /
перенос на другой сервер). Всё, что нужно знать в одном месте.

---

## 0. Что это
Telegram Mini App проката мотоциклов на Пхукете: каталог байков и аренда,
корзина+заказы, доставка, лояльность и рефералы, игра-заезд, админ-панель. Стек:
Rust (axum backend + Dioxus/WASM frontend), Postgres (SeaORM), teloxide-бот.
Хостинг: Railway (авто-деплой при push в `main`).

## 1. Подготовка
- Telegram-бот: создай у @BotFather → получишь **BOT_TOKEN** и @username.
- В @BotFather → Bot Settings → Menu Button / Web App → укажи URL мини-аппа
  (получишь после деплоя, шаг 4) — `https://<твой-домен>`.
- Аккаунт Railway (railway.app), подключённый к GitHub-форку этого репозитория.

## 2. Репозиторий
```bash
git clone <этот-репозиторий> my-shop && cd my-shop
cp .env.template .env          # заполни значения (см. комментарии в файле)
```
Ключевые переменные (полный список — в `.env.template`):
- **BOT_TOKEN**, **DATABASE_URL** — обязательны.
- **ADMIN_IDS** — твои Telegram-id через запятую (доступ в админку + уведомления).
- **ADMIN_PASSWORD** — пароль входа в админ-панель.
- **WEB_APP_URL / APP_URL** — публичный URL мини-аппа.
- **S3_\*** — опционально, для постоянного хранения загруженных фото/видео
  (без них загрузки кладутся в эфемерный `/data/uploads` и пропадают на редеплое).

## 3. База данных
- В Railway-проект добавь плагин **PostgreSQL** → он выдаст `DATABASE_URL`.
- Миграции применяются **автоматически при старте** бэкенда и каждая выполняется
  **ровно один раз** (таблица `_schema_migrations`). Менять каталог руками в БД не
  нужно — правки делаются в админке и больше не затираются миграциями.
- Стартовые данные засеваются сид-миграциями **только на пустой базе**. На
  рабочей базе сиды не трогают твои данные.

## 4. Деплой на Railway
- Подключи репозиторий к Railway (GitHub integration) → **push в `main`
  авто-деплоит**. Dockerfile собирает бэкенд (musl) и КОПИРУЕТ готовый `dist/`
  (фронт НЕ собирается в Docker — см. шаг 6).
- В Service Variables пропиши все переменные из `.env`.
- После первого деплоя возьми публичный URL и вставь в @BotFather (Web App URL)
  и в `WEB_APP_URL/APP_URL`.

## 5. Загрузки (S3, опционально, но рекомендуется)
- Заведи S3-совместимое хранилище (Storj/MinIO/Backblaze/Railway bucket).
- Пропиши `S3_BUCKET / S3_ACCESS_KEY_ID / S3_SECRET_ACCESS_KEY / S3_ENDPOINT /
  S3_PUBLIC_URL / S3_REGION`.
- Без S3 загрузки фото/видео работают, но не переживают редеплой.

## 6. Фронтенд (важно!)
`dist/` коммитится в репозиторий и КОПИРУЕТСЯ Docker'ом — Docker его НЕ собирает.
Любое изменение в `src/ui/**` требует пересборки фронта ПЕРЕД пушем:
```bash
./scripts/build-frontend.sh          # trunk build --release + cache-bust
./scripts/predeploy-smoke.sh --no-build   # ОБЯЗАТЕЛЬНО: грузит dist в реальном Chrome
git add dist && git commit && git push
```
`cargo`/`trunk` только КОМПИЛИРУЮТ wasm — не запускают его, поэтому ошибки загрузки
модуля (версия wasm-bindgen и т.п.) проходят все зелёные проверки и ломают прод.
Поэтому smoke-тест перед пушем — обязателен.

## 7. Ассеты (логотип, спрайты игры, картинки)
- Все статич. ассеты лежат в `assets/` и `styles/` (в репо).
- Перенос/бэкап: `./scripts/export-assets.sh` → `exports/woody-assets-<дата>.tar.gz`
  (+ manifest + sha256). Восстановление: `tar -xzf <архив> -C <repo-root>`.
- Замени `assets/logo/*`, `assets/packs/*` на свой брендинг по желанию.

## 8. Уведомления о деплое
- Бэкенд при каждом успешном деплое шлёт всем `ADMIN_IDS` в Telegram, ЧТО
  задеплоено (коммит) — `notify::notify_deploy` (данные из Railway-env).
- Опционально lefthook `pre-push` шлёт «деплой запущен», если выставить
  `DEPLOY_NOTIFY_BOT_TOKEN` + `DEPLOY_NOTIFY_CHAT_ID`.

## 9. Git-хуки (lefthook)
```bash
brew install lefthook && lefthook install
```
Хуки: запрет прямого коммита/пуша в `main`, conventional-commits, cargo fmt/check,
defensive-тесты, frontend-smoke на пуше, deploy heads-up.

## 10. Первый запуск — чеклист
- [ ] BOT_TOKEN + DATABASE_URL заданы, бэкенд поднялся (`/healthz` = 200).
- [ ] Web App URL прописан в @BotFather, мини-апп открывается.
- [ ] ADMIN_IDS = твой id, админка открывается, товары добавляются/сохраняются.
- [ ] (опц.) S3 настроен — загрузка фото переживает редеплой.
- [ ] Пришло уведомление «🚀 Новый деплой на проде».

Поддерживаемые памятки и история решений — в коммитах (`git log`) и в отчётах
